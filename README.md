## 1. 개요

**TRINITY**는 유튜브 링크 공유(Share Sheet) 또는 이미지 업로드로 전달된 미디어가 **AI로 생성·조작되었는지**를 판별하는 **3축 앙상블 탐지 시스템**입니다. 사용자는 Flutter 크로스플랫폼 앱(경량 클라이언트)으로 요청을 보내고, 분석은 Apple Silicon 맥북에서 구동되는 **셀프호스팅 엣지 서버**(FastAPI)가 수행합니다. 영상을 상용 클라우드에 업로드하지 않는 구조로 프라이버시 노출을 최소화합니다.

Sora·Veo 등 확산 모델 기반 영상 생성 기술은 인간의 시각적 인지 능력을 넘어서는 극사실적 결과물을 만들어내고 있으며, 위협 모델도 "얼굴 교체 딥페이크"에서 **"완전 생성 영상"**으로 이동했습니다. 최신 서베이(ACL Findings 2026)는 이 변화를 **"아티팩트 매칭 → 사실적 충실도 검증(Factual Fidelity Verification)"의 패러다임 전환**으로 정의합니다. 공간 픽셀 단서에만 의존하는 단일 모델 탐지기는 압축·노이즈·리사이즈 같은 통상적 유통 과정에서 단서를 잃고, 학습에 없던 생성기(Unseen Generators) 앞에서 일반화에 실패합니다. TRINITY는 **서로 실패 모드가 겹치지 않는 세 가지 단서**를 결합해 이 한계를 돌파합니다.

추가로, 분석 결과를 **유튜브 채널 ID 단위로 누적**하여 "이 채널에서 분석된 N개 영상 중 M개가 AI 생성 의심" 같은 채널 신뢰도 맥락을 함께 제공합니다.

## 2. 시스템 파이프라인

1. **Flutter 앱**: 유튜브 공유 시트로 링크 수신, 또는 갤러리에서 이미지 업로드 → REST API 호출
2. **제어**: FastAPI 비동기 처리 — 요청 접수(job_id 반환) → 백그라운드 분석 → 폴링으로 진행률·결과 조회. 이미지는 처리 시간이 짧아 동기 응답.
3. **수집**: 영상 트랙은 `yt-dlp` 다운로드 + 채널 ID 추출, 이미지 트랙은 파일 직수신
4. **전처리**: 전/중/후 구간 다중 프레임 샘플링(3-Point Biopsy). **강제 리사이즈 금지** — 고주파 위조 흔적 보존을 위해 원본 해상도 패치를 유지하는 Native-Scale 원칙 적용
5. **분석**: 3축 병렬 실행 → 무결성 충돌 교차 감사 → 동적 가중 융합 → 위험 점수 + 판단 근거 산출
6. **저장/반환**: 결과를 채널 이력에 누적하고 앱에 반환. 앱은 **결과(요약) → 탭하면 결과 해설(상세)** 순서로 화면을 전환합니다.

## 3. 3축 탐지 엔진

### 제1축 — 신호 (Signal / Frequency)
> *"생성 모델의 업샘플링 연산은 주파수 도메인에 주기적 스펙트럼 이상을 남긴다."*

- **원리**: 생성 모델의 목적 함수는 주파수 정보를 상대적으로 무시하도록 설계되어 있어, 진짜/생성물 간 불일치가 공간 도메인보다 주파수 도메인에서 증폭됩니다(귀납적 편향 관점, arXiv:2502.19716). 픽셀 도메인에서는 보이지 않는 이 흔적이 FFT/DCT로 투영하면 격자 피크·스펙트럼 이상으로 드러나며, 고대역 마스크 필터링 후 iFFT로 재구성한 **스펙트럼 잔차 맵**은 텍스처 이상과 주기적 그리드 아티팩트를 강하게 부각시킵니다.
- **주의할 점 — "촬영 영상도 주파수가 다 똑같이 나오지 않나?"**: 실촬영 영상도 카메라·ISO·압축 설정에 따라 고주파 에너지 총량은 제각각입니다. 그래서 **에너지 총량만으로는 절대 판별하지 않습니다.** 판별의 핵심은 총량이 아니라 **주기적 격자 구조의 위치** — 업샘플링 연산이 남기는 흔적은 나이퀴스트 대역 근처의 특정 위치에 규칙적으로 나타나는 반면, 실촬영 노이즈(센서·렌즈 회절)는 비주기적·광대역입니다. 구현은 **강도 × 위치**를 함께 게이팅해 이 둘을 구분합니다.
- **구현**: ① 규칙 기반 스코어러(방사 파워 스펙트럼의 멱법칙 이탈 + 격자 피크 강도·위치 게이팅), ② 공간-주파수 하이브리드 어텐션(CBAM + 게이트 융합, 학습형), ③ 주파수 도메인 마스킹 학습 — 특정 대역 과적합 방지.
- **강건성 근거**: 2026년 강건성 정량화 연구에서 가우시안 블러가 JPEG 압축 대비 평균 30배 파괴적임이 확인됨 — 압축 위주인 유튜브 재인코딩 환경에서 주파수 단서는 상당 부분 생존합니다. 저화질 입력에는 품질 게이팅으로 가중치를 낮춥니다.

### 제2축 — 출처 (Provenance)
> *"양성은 강한 증거, 음성은 무정보 — 그리고 양성조차 절대적이지 않다."*

| 기술 | 삽입 위치 | 성격 | 내구성 |
|---|---|---|---|
| **C2PA** | 파일 메타데이터 헤더(서명된 매니페스트) | 제작자·도구·편집 이력 등 정보 풍부 | 낮음 — 재인코딩·스크린샷·플랫폼 업로드로 유실 |
| **SynthID류** | 콘텐츠 자체(픽셀/스펙트로그램) | AI 생성 여부만 표시(정보 빈약) | 높음 — 압축·크롭·리사이즈·색보정 생존 |

- **판정 정책**: 워터마크/매니페스트 신호는 **긍정 증거로만** 사용합니다. 음성은 "정보 없음"입니다 — 다수 생성기가 워터마크를 넣지 않으며, 확산 정제(diffusion purification) 재생성 공격으로 상용 워터마크도 세탁될 수 있음이 증명되었습니다(NeurIPS 2024). **"양성 → 즉시 확정(Early-Exit)" 정책은 폐기**했습니다 — 진짜 미디어에 워터마크를 덧칠해 가짜로 몰아가는 스푸핑(mark-to-frame) 공격이 실증되었기 때문입니다(탐지기 EER 16%→75% 급등, arXiv:2606.23335). 양성 시에도 제1·3축의 교차 확인을 반드시 병행합니다.
- **무결성 충돌 교차 감사 ★프로젝트 기여점 (`audit.py`)**: C2PA 검증(메타데이터 서명 확인)과 워터마크 검출(픽셀 신호 디코딩)은 서로를 참조하지 않는 독립 절차라서, "사람이 편집함"을 주장하는 유효한 C2PA 매니페스트와 "AI 생성"을 알리는 픽셀 워터마크가 한 파일에 공존할 수 있습니다 — 이른바 **"인증된 가짜(Authenticated Fakes)"** (CVPR 2026 Workshops). 두 계층을 충돌 매트릭스로 교차 감사해, 유효 매니페스트의 주장과 워터마크 신호가 모순되면 **세탁 의심 신호로 승격**합니다.

  | C2PA 주장 | 워터마크 | 판정 |
  |---|---|---|
  | 서명 무효 | — | 변조 의심 |
  | AI 생성 | 검출 | 두 계층 일치 (가장 강한 증거) |
  | AI 생성 | 미검출 | 워터마크 제거 의심 |
  | **사람 편집** | **검출** | **★무결성 충돌 — 출처 세탁 의심** |
  | 매니페스트 없음 | 검출 | 단일 계층 증거 |
  | 매니페스트 없음 | 미검출/미가용 | 정보 없음 (진본 증명 아님) |

  원 논문은 **이미지 모달리티**에서만 이 감사를 검증했고 영상 확장은 미해결 과제로 남겼습니다. TRINITY는 영상 트랙으로 확장합니다 — 컨테이너에 매니페스트 하나 : 프레임마다 워터마크라는 비대칭 구조 때문에, **프레임별 워터마크 검출률이 20~80%인 경우 → 생성 클립과 실촬영 구간이 혼재한 부분 합성 의심**이라는, 이미지에 없는 새로운 상태를 판별합니다.
- **구현 현실**: SynthID 검출은 구글 비공개 인프라가 필요하므로(제3자 독립 구현 불가), Content Detection API 승인 전까지는 **인터페이스만 정의된 플러그인 슬롯**으로 유지합니다. `UNAVAILABLE`(탐지기 미연결)과 `NOT_DETECTED`(스캔했으나 미발견)를 엄격히 구분합니다 — 둘 다 "진짜"를 뜻하지 않지만 의미가 다르기 때문입니다.

### 제3축 — 의미·물리 (Semantic & Physics)
> *"픽셀은 완벽해도, 의미의 분포와 물리 법칙은 속이기 어렵다."*

- **분포 편차 + 의미 감산**: 동결된 비전 인코더(CLIP-ViT 등) 특징 공간에서 실제 이미지 분포로부터의 마할라노비스 편차를 측정하되, 모델이 피사체의 의미를 판별 기준으로 암기하는 **의미론적 지름길**을 수학적으로 차단합니다 — SVD로 의미 우세 부분공간을 추정·감산하거나 마스킹 미세튜닝을 적용합니다.
- **시공간 일관성 (영상 전용)**: 인접 프레임 간 정체성 흔들림, 모션 불연속, **시간 에너지 비율**(공간 구조 대비 시간 변화량)을 측정합니다. 장면 전환(컷 편집) 시 이를 "정체성 흔들림"으로 오인하지 않도록 신뢰도를 하향합니다.
- **NSG 근사에 관한 고지**: 원 논문(NeurIPS 2025)의 NSG는 사전학습 확산 모델로 공간 확률 그래디언트를 추정합니다. 맥북 엣지 서버에서 프레임마다 확산 모델을 돌리는 것은 비현실적이므로, 현재는 **밝기 기반 시공간 그래디언트 비율로 근사**합니다 — 근사이며 원 논문의 성능을 담보하지 않습니다.
- **스코프 주석**: 최신 서베이의 4계층 분류(내재 단서 → 시공간 일관성 → 크로스모달 → LLM 세계 추론) 중 본 프로젝트는 1~2계층 + 분포 편차를 구현하며, 3~4계층은 Future Work로 명시합니다.

### 융합 — 동적 가중 앙상블

기본 가중치는 신호 0.40 / 출처 0.35 / 의미 0.25이며, 아래 조건에 따라 실시간 재조정됩니다.

| 조건 | 동작 |
|---|---|
| 제2축 양성 | 고신뢰 가중(최대 0.60) + 제1·3축 교차 확인 — 즉시 확정하지 않음 |
| 무결성 충돌 감지 | 세탁 의심으로 위험도 승격, 전 축 정밀 분석 |
| 제2축 음성 | 제1축 + 제3축 융합이 주력 |
| 저화질/블러성 열화 입력 | 제1축 가중 0.5배 하향, 제3축 1.4배 상향 |
| 축이 적용 불가 | 해당 축 가중 0 — 게이트 사유를 결과에 명시 |
| 얼굴 유무 | 무관 — 전 축이 인물 없는 완전 생성 영상에도 동작 |

최종 위험도는 **낮음 / 주의 / 높음** 3단계로 산출되며, 근거가 빈약한 경우(신뢰도 0.3 미만) 점수가 낮아도 "안전"으로 단정하지 않고 "주의"로 보고합니다.

## 4. 왜 3축인가

세 축은 임의로 고른 것이 아니라, 이 분야에 **이미 확립된 두 개의 분류 체계를 교차**시킨 결과입니다.

**① 패시브(콘텐츠 기반) vs 액티브(출처증명) — 표준 대분류.** 2026년 리뷰 논문("A Review of Tools and Technologies to Combat Deepfakes", *Information* 저널, DOI:10.3390/info17040347)은 "실전에서 가장 강력한 접근은 출처증명·워터마킹·콘텐츠 기반 탐지·사람의 감독을 결합한 **계층적 방어(layered defense)**"라고 결론짓습니다. 업계 자료 역시 "기업용 탐지 도구 대부분이 패시브 포렌식 분석과 출처증명 검증을 층층이 결합해 통합 신뢰도 점수를 낸다"고 보고합니다. 이 구분에서 **제2축(출처)이 액티브**, **제1·3축이 패시브** 쪽에 해당합니다.

**② 저수준 아티팩트 vs 고수준 의미 — 패시브 탐지 내부의 확립된 분화.** 두 계층을 가르는 기준은 **"탐지에 장면 이해가 필요한가"**입니다.

| | 저수준 (Low-level) | 고수준 (High-level) |
|---|---|---|
| **정의** | 픽셀 단위 통계적 이상 · 합성 경계 불일치 | 물리적·생물학적 타당성 위반 |
| **예시** | 업샘플링 노이즈, 스펙트럼 격자 피크, 블렌딩 이음새, 압축 아티팩트 | 조명 방향 불일치, 부자연스러운 그림자·반사, 시공간 연속성 붕괴 |
| **판별 조건** | **이미지 내용과 무관하게** 발생 — 무엇을 찍었는지 몰라도 탐지 가능 | 모델이 장면 맥락을 **"이해"해야만** 탐지 가능 |
| **대응 축** | **제1축 (신호)** | **제3축 (의미·물리)** |

이 분화는 본 프로젝트가 제3축 근거로 인용한 **Hou et al. (ACL Findings 2026, arXiv:2607.10787)** 이 직접 정의한 것입니다 — 해당 서베이는 이 분야가 **"저수준 검사에서 고수준 의미론적 검증으로 이행하는 패러다임 전환"** 중이라고 규정하고, 4계층 분류(내재 단서 → 시공간 일관성 → 크로스모달 → 언어유도 세계추론)를 제시하는데 **첫 계층이 저수준, 나머지가 고수준**에 해당합니다. 경계의 조작적 정의는 **Alpha Blending Hypothesis (arXiv:2605.10334)** 가 명시했고("고수준 오류는 모델이 장면을 이해해야 하지만, 저수준 아티팩트는 이미지 내용과 무관하게 발생한다"), **TriDF (arXiv:2512.10652)** 의 *Quality Artifacts* vs *Semantic Artifacts* 이분법도 같은 경계를 채택합니다.

**두 이분법을 교차하면 정확히 3개의 칸이 나옵니다**: 액티브(제2축) / 패시브-저수준(제1축) / 패시브-고수준(제3축). TRINITY의 기여는 이 세 칸을 각각 구현한 데 그치지 않고, **패시브와 액티브의 경계선 위에서 발생하는 문제**(무결성 충돌 — §3의 ★표시)까지 다룬다는 데 있습니다. 즉 "임의로 3개를 골라 앙상블했다"가 아니라 "확립된 분류 체계의 교차점을 빠짐없이 채우고, 그 경계의 모순까지 다뤘다"는 것이 구조적 근거입니다.

## 5. 투트랙: 이미지 + 영상

세 축 모두 본질적으로 프레임 단위 분석이므로, 코어 모듈을 100% 공유하고 입력 어댑터만 분기합니다.

| 축 | 이미지 트랙 | 영상 트랙 |
|---|---|---|
| 1축 신호 | ✅ (압축 적어 신호 선명) | ✅ 다중 프레임 집계 + 원본 해상도 패치 |
| 2축 출처 | ✅ C2PA + 워터마크 + 교차 감사 | ⚠️ 재인코딩 시 C2PA 유실 가능, 워터마크는 생존 — **영상 교차 감사는 본 프로젝트가 개척** |
| 3축 의미 | ✅ 분포 편차 + 의미 감산 | ✅ 분포 편차 + 시공간 일관성 + NSG 근사 |

## 6. 벤치마크 검증 체계

투트랙 구조에 맞춰 영상·이미지 벤치마크를 각각 구성합니다. 학부 졸업작품의 연산 자원(MacBook Air) 현실을 고려해, **실제 평가를 실행할 대상**과 **설계 근거·문헌 비교용 참조**를 구분합니다.

### 6.1 영상 트랙

| 벤치마크 | 규모/특징 | 역할 | 실행 |
|---|---|---|---|
| **GenVidBench** (AAAI 2026) | 678만 영상, 11개 SOTA 생성기, **교차 소스 + 교차 생성기** | 일반화 성능 1차 관문 — 가장 엄격 | ✅ 경량판 GenVidBench-143k |
| **GenVideo / DeMamba** (*Sci. China Inf. Sci.* 2026) | 100만+ 영상, T2V·I2V 포괄, degraded video 태스크 | 유통 압축·화질 열화 저항성 | 참조 |
| **RobustSora** (2025.12) | 워터마크 제거(De-watermarked) 영상 중심 | 워터마크 회피 공격 하 제1·3축 독립 성능 | 참조 |

**GenVidBench를 1차 관문으로 두는 이유**: GenVideo의 교차 생성기 설계는 "훈련에 없던 생성기로 테스트"까지만 통제하지만, GenVidBench는 여기에 **교차 소스**(같은 피사체·장면이 훈련/테스트에 겹치지 않도록 분리)를 더해, 탐지기가 "무엇을 보여주는가"가 아니라 "어떻게 생성됐는가"만으로 판별하도록 강제합니다 — 제3축의 의미론적 지름길 문제를 데이터셋 설계 단계에서부터 차단하는 접근입니다.

### 6.2 이미지 트랙

| 벤치마크 | 규모/특징 | 역할 | 실행 |
|---|---|---|---|
| **GenImage** (NeurIPS 2023) | 268만 장(ImageNet 실사진 133만 + 8개 생성기 135만), cross-generator + degraded 태스크 | 일반화 성능의 기준점 | ✅ 부분 서브셋 |
| **WildFake** (AAAI 2025) | 오픈소스 커뮤니티 수집, GAN·디퓨전 계층 구조 | 실전 다양성 검증 | 참조 |
| **MIRAGE** (AAAI 2026) | 동일 커뮤니티 출처로 도메인 편향 차단, 파인튜닝·후처리 파이프라인 포함 | 도메인 편향 없는 최종 스트레스 테스트 | 참조 |

> GenImage는 제3축 설계 근거로 인용한 MPFT/TAM의 성능 수치(98.2%)가 측정된 데이터셋입니다.

### 6.3 평가 원칙

- 실행 대상은 **경량판/서브셋 우선** — 임계값 재보정과 파이프라인 검증이 목적이며, 전체 규모 학습은 자원 제약상 범위 외입니다.
- 참조 벤치마크는 **설계 결정의 근거와 한계 서술**에 사용하며, 미실행 사실을 결과 보고 시 명시합니다.
- 절대 성능 수치는 실제 데이터셋 평가 이후에만 주장하며, 그 이전 단계의 검증은 "판정 방향과 근거의 타당성 확인"으로 한정해 기술합니다.

## 7. 학습 데이터 위생 — 지름길 학습 차단

2024~2026 문헌은 각 축에서 같은 병리의 변종을 독립적으로 보고했습니다: **탐지기는 항상 가장 값싼 상관관계를 암기한다.** TRINITY는 아래 차단책을 학습 파이프라인의 요구사항(`training/hygiene.py`)으로 명문화합니다.

| # | 지름길 | 발생 원인 | 차단책 (근거) |
|---|---|---|---|
| 1 | "고주파 풍부 = 가짜" | 진짜(웹 재압축) vs 가짜(원시 생성)의 압축 비대칭 | DDA식 압축·스펙트럼 정렬 (NeurIPS 2025) |
| 2 | "워터마크 = 가짜" | 합성물에만 워터마크가 존재하는 훈련 데이터 | 양 클래스 워터마크 탈상관 (arXiv:2606.23335) |
| 3 | "특정 피사체 = 가짜" | 생성 데이터셋의 의미 분포 쏠림 | 의미 부분공간 감산(SVD) 또는 마스킹 미세튜닝 |
| 4 | **"특정 촬영 스타일 = 진짜"** | 실사진과 생성물을 서로 다른 출처에서 수집 → 탐지기가 생성 흔적이 아니라 출처별 촬영·후처리 스타일을 암기 | 동일 출처 수집 또는 출처 분포 정렬 (MIRAGE, AAAI 2026) |

4번은 1번과 같은 계열이지만 압축이 아닌 **수집 경로 자체**에서 발생한다는 점에서 별도 항목입니다. 훈련 전 네 항목을 점검하고, 평가는 6장의 벤치마크로 스트레스 테스트합니다.

## 8. 서버 하드웨어 전략 (Apple Silicon 엣지 서버)

- **FFT/주파수 변환 → CPU(AMX)**: PyTorch `torch.fft`는 MPS 백엔드에서 2의 거듭제곱 텐서 제약과 복소수 처리 이슈가 보고되어, CPU 행렬 보조프로세서 경로로 우회합니다.
- **출처 스캐닝·교차 감사 → 효율 코어**: 암호학적/논리 연산이므로 효율 코어 백그라운드 스레드에서 파일 로딩과 동시 수행합니다.
- **ViT/CNN 추론 → CoreML(ANE)**: FP16 정적 양자화 후 Neural Engine 할당 — MPS 대비 약 1.5배 속도 향상이 보고된 경로입니다.
- **열 관리**: 팬리스 구조의 열 스로틀링을 감안한 분할 실행으로 안정적 처리량을 유지하고, 데모 시에는 Cloudflare Tunnel로 외부 접근을 제공합니다.

## 9. Flutter 클라이언트 & 접근성

- **진입**: OS 공유 시트("TRINITY로 분석") 또는 앱 내 링크 붙여넣기/이미지 업로드
- **화면 흐름**: 홈 → (영상만) 분석 중 → **결과 요약** → 탭하면 **결과 해설**(축별 상세 근거) → 채널 상세 — 탭바 없는 스택 네비게이션
- **디자인**: Bold Typography 다크 테마 (배경 `#0A0A0A`, 버밀리언 액센트 `#FF3D00`, Inter Tight + JetBrains Mono, 모서리 반경 0)
- **신호등 메타포**: 초록(낮은 위험) / 노랑(주의) / 빨강(높은 위험) 3단계 위험도 + 축별 근거 칩
- **취약 계층 배려**: 고대비 팔레트, 동적 글꼴 크기, 화면 낭독기(VoiceOver/TalkBack) 연동, 판독 결과 TTS 음성 안내 — 딥페이크 금융 사기의 주요 표적인 노년층의 골든타임 확보가 목표
- **향후 추가 예정**: 결과 해설 화면에 스펙트럼 잔차 히트맵(제1축)·블록별 시공간 불안정성 히트맵(제3축) 등 시각적 증거 표시. 판정 정확도 자체를 개선하는 기능이 아니라 **설명 가능성 강화** 목적이며, 임계값 재보정 이전 단계임을 UI에 함께 명시할 예정.

## 11. 한계 및 주의

- 제2축 **음성은 진본 증명이 아니며**, **양성 역시 절대적이지 않습니다**(mark-to-frame 스푸핑 실증) — 교차 감사와 타 축 병행으로 완화하되, 잔여 위험을 명시합니다.
- 의미론 기반 탐지는 지름길 학습 위험이 있어 **제1축과의 앙상블 + 7장의 위생 절차를 전제**로만 동작합니다.
- 현재 NSG는 근사 구현이며, 정식 확산 모델 기반 구현은 Future Work입니다.
- 크로스모달·LLM 세계지식 추론 계층은 범위 외이며 Future Work로 명시합니다.
- 본 시스템은 **위험도 점수**를 제시하며 단정적 판정을 내리지 않습니다.
- `yt-dlp` 기반 다운로드는 플랫폼 약관상 회색지대로, 본 프로젝트는 **학술 연구 목적**으로만 사용합니다.
- GenVidBench는 CC BY-NC 4.0(비영리) 라이선스입니다 — 학술 용도에는 제약이 없으나, 향후 상용화 시 재검토가 필요합니다.
